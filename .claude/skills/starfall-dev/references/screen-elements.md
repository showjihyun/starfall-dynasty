# 화면 요소 — 자동 검증으로 잡고, 사람은 r1 전에 한 번 본다

2026-10-05, p1-02-mining 회고에서 만든 문서다. 계약 114 항목 중 r3에서 112 PASS를 받았지만, 첫 사람 세션(SC-68)에서야 디자인 §8의 화면 요소 셋이 **아예 구현되지 않았다**는 게 드러났다(광맥 3D 표식, 채굴 가능 표시, 쿨다운). 채굴 키는 롤 키와 겹쳐 있었다.

## 1. 왜 놓쳤나

1. **화면 요소를 잡는 자동 항목이 없었다.** 디자인 §8의 여섯 요소가 계약에서는 사람 관찰 항목 하나(SC-68)로 뭉쳐 있었다. 요소별 테스트가 없으니 빠진 요소가 있어도 초록이었다. 검증 규율의 "초록불은 아무것도 재지 않는다"와 같은 형태다.
2. **구현자가 사람 확인을 넘기지 않았다.** C3(그레이박스 채굴 UI) 구현 기록의 "사람이 확인할 항목"에는 "없음"이 남아 있었다.
3. **사람 세션이 맨 끝에 있었다.** r3와 CI까지 끝난 뒤에야 처음 Play를 눌렀다. 그래서 FAIL이 마감 직전에 나왔고, 고치는 데 구현자 재투입과 재세션이 필요했다.
4. **세션 준비가 반복해서 틀렸다.** Editor를 환경 변수 없이 띄워 빈 씬이 나왔다(p1-01 R21과 같은 실수). 서버 실행 한도가 벽시계 기준이라 PC 절전 중에 한도가 다 지나 버렸다.

## 2. 규칙

### S1. 디자인은 화면 요소를 번호 붙은 표로 쓴다 (Phase 2, designer)
- 화면 절은 `UI-01`, `UI-02`처럼 요소마다 행을 둔다. 열은 네 개다: 보이는 것, 데이터 출처(어느 메시지나 data 값), 상태 변화(언제 바뀌고 언제 사라지는가), 조작 키.
- 조작 키는 기존 바인딩 표와 대조해 겹치지 않음을 적는다.

### S2. 계약은 화면 요소마다 자동 항목 둘과 사람 체크 한 줄을 둔다 (Phase 3, qa)
요소(`UI-nn`)마다 아래 세 가지를 계약에 둔다. 사람 관찰 항목 하나로 뭉치지 않는다.
1. **표시 로직 테스트(EditMode)** — 그 요소가 보여줄 값과 상태(문자열, 색 구분, 보임/숨김, 경계값)를 MonoBehaviour 밖 순수 함수로 계산한다. 계약에 테스트 이름을 적는다. 기대값은 data 원본이나 스펙에서 독립적으로 정한다.
2. **존재 단언(PlayMode)** — 세션이 시작된 씬에 그 요소가 **실제로 만들어졌는지** 단언한다. 예: 광맥 수만큼 표식 GameObject가 있다, HUD 행 목록에 그 요소의 행이 있다, 키 입력이 그 동작을 일으킨다. 표시 로직이 맞아도 화면에 붙지 않았으면 이 항목이 FAIL이다. ⊘에는 "요소가 0개여도 통과"를 막는 분모(기대 개수)를 적는다.
3. **사람 체크 한 줄** — S4 사전 세션과 최종 세션에서 사람이 예/아니오로 답할 문장이다.

### S3. 화면을 건드린 모듈의 완료 점검 (Phase 4, client·techart)
`qa-throughput.md` R3의 자기 점검에 더해 다음 둘을 확인한다.
- 담당 `UI-nn`마다 표시 로직 테스트와 PlayMode 존재 단언이 계약 이름으로 실행되고, 구현을 망가뜨리면 실패한다.
- `03_*_impl.md`의 "사람이 확인할 항목"에 담당 `UI-nn`의 체크 문장과 조작 키를 적는다. 화면을 건드린 모듈이 **"없음"으로 둘 수 없다.**

### S4. 사람 사전 세션은 r1 전에 한 번 한다 (Phase 4 끝, 리더)
- 화면 요소를 가진 모듈이 모두 완료되면, 리더가 r1 동결 **전에** 사용자에게 15분 사전 세션을 청한다.
- 준비는 리더가 `tests/e2e/unity_session.py start --slice <id> --tag <SC> --new-world`로 한다. 이 도구가 아래 순서를 그대로 수행하고, 사용자가 Play를 누르면 `status`로 접속을 확인하고, 끝나면 `stop`으로 서버를 내린다. 수동으로 할 때의 순서는 다음과 같다.
  - 발견 같은 1회성 사건을 보려면 새 월드를 만든다.
  - 서버는 `server_boot.py serve`로 띄운다. 실행 한도는 넉넉히 잡고, 끝날 때 stop 파일로 stdin `shutdown`을 보낸다.
  - **Editor는 리더가 띄운다.** 사용자에게 Editor를 닫아 달라고 한 뒤 `STARFALL_GREYBOX_AUTOBUILD=1`·`STARFALL_NET_AUTOCONNECT=1`과 `.env`의 dev 비밀값을 **그 프로세스 환경에만** 넣고, `-logFile`을 증거 디렉터리로 준다. 로그 파일이 생겼는지와 서버의 `live_connections`로 접속을 확인한다.
- 사용자에게는 S2의 사람 체크 문장, 조작 키, 각 장면에서 해야 할 동작을 표로 준다.
- 사전 세션의 답은 리더가 `evidence/{세션}/notes.md`에 원문 그대로 적는다. "아니오"는 r1 전에 고칠 결함 목록이 된다. 이 세션은 판정이 아니다. 판정은 r1 이후 최종 세션이 한다.
- 최종 세션에서 스크린샷은 사용자에게 부담이 크다. 계약은 사람 판정 입력을 **요소별 예/아니오 답 + 서버 기록**으로 정하고, 스크린샷은 선택으로 둔다.
