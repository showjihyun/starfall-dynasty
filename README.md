# STARFALL DYNASTY — Rust 3D 우주 멀티플레이어

> THE GALAXY IS NOT A MAP. IT IS A HISTORY.

`기획안/`의 설계를 Rust로 구현한 수직 슬라이스. 권위 서버(Rust/tokio) + 3D 클라이언트(Bevy 0.20) + 역사 엔진.
함선 모델은 Blender 5.2에서 헤드리스 Python으로 모델링·베이크했고(`tools/blender/`), 우주·함선 셰이더와 이펙트는 WESL로 작성했다.

## 빠르게 실행

```
cargo run -p server --release
cargo run -p client --release
```

다른 PC에서 접속: `cargo run -p client --release -- --server ws://<서버IP>:7777`

## 게임 개요

- **함선은 단 한 척, 성장형** — 캐릭터 생성 때 5종 중 하나(Wren / Talon / Bastion / Mule / Seer)를 고르면 평생 교체할 수 없다. 8개 모듈을 Lv1→Lv10으로 올리면 그 한 척이 자란다:
  - **Rank 0–2 소형함**: 1인 전투기. 기수 레이저로 직접 조준하는 도그파이트.
  - **Rank 3–6 순양함**(120–200 m): 360° 자동 조준 포탑 포대, 함수포, 호위함 1–2척.
  - **Rank 7–10 주력함**(350–650 m): 은하영웅전설식 함수 주포 빔 일제사, 포탑 10–16문, 호위 함대 3–4척. 거대한 만큼 느리게 선회하지만 내구도·사거리가 압도적.
  - 모듈 상한(Lv5에서 시작)은 시나리오를 돌파할 때마다 +1이므로, 주력함은 캠페인을 진행해야 도달한다.
- **업그레이드 재료**는 일일 미션, 교전(해적 격파·함대전 승리·현상금), 시나리오 돌파, 채굴·정제·판매, 탐험(스캔)으로 얻는다. 모듈 상한은 Lv5에서 시작하고 **시나리오 한 장을 돌파할 때마다 +1**.
- **탐험** — 10개 성계(위험도 CORE → FRONTIER → WILD → WAR ZONE → DEEP). 워프 거리는 워프 코어 레벨에 비례하고, The Deep은 업그레이드해야 닿는다. 이상현상·유적·잔해·신호·고대 게이트를 스캔하면 보상이 있고, 최초 발견은 연대기에 남는다.
- **동맹 전쟁** — 함장들이 동맹(태그 [ABC])을 창설·초대한다. 동맹원끼리는 서로 공격할 수 없다. 맹주가 다른 동맹에 선전포고하면 CORE를 제외한 모든 성계에서 범죄 기록 없이 교전할 수 있고, 강화로 끝낼 수 있다. 결성·선전포고·강화·동맹 대 동맹 전투는 모두 연대기에 기록된다.
- **네트워크 교전** — 같은 성계의 모든 함장이 실시간으로 보인다(20 Hz 서버 권위 시뮬레이션). 함대(최대 5척)는 아군 사격 없이 보상을 공유한다. WILD에서 무고한 함장을 공격하면 수배·현상금, WAR ZONE은 자유 교전. 함대 대 함대 교전이 끝나면 「제N차 ○○ 전투」로 연대기에 기록된다.
- **역사 엔진** — 행동 → DomainEvent → 중요도 판정 → 연대기/전기/Herald 뉴스. 격침된 함선의 잔해는 7일간 남고, 다른 함장이 잔해를 조사해 봉인된 함선 로그(증거)를 얻은 뒤 연구를 발표하거나, 증거를 쥔 함장이 반박할 수 있다. 반박이 쌓이면 「역사 논쟁」이 새 사건이 된다. 이벤트 소싱(JSONL)으로 저장되어 재시작 시 리플레이로 복원된다.

화면 중앙 조준선 좌우의 호 게이지가 실드(좌)·선체(우)이고, 방금 잃은 양이 주황 잔상으로 남았다가 줄어든다. 선체 피격 시 화면 테두리가 붉게 번쩍인다.

### 우주 좌표

- **은하 좌표** `G(x, y, z) ly` — Sol Haven 기준 광년 단위.
- **섹터** — 은하 전도를 1광년 칸으로 나눈 이름(열 문자 + 행 숫자). Sol Haven은 `D1`, The Deep은 `C7`.
- **로컬 좌표** `L(x, y, z) km` — 성계 안에서 항성 기준, 북쪽은 -Z. 방위각(0°=북, 시계방향)과 고도각을 함께 표시한다.

## 개발 하네스

게임 자체를 에이전트가 재현·조종·수치 검증할 수 있게 설계하는 원칙(「게임 개발용 AI 하네스를 설계하는 법」)을 근거로 도입했다. 원칙별 현황, 이번에 적용한 핵심, 로드맵은 [docs/HARNESS.md](docs/HARNESS.md)에 있다.

- **기록·재생**: `server --record DIR`로 기록하고 `cargo run -p sim --release --example replay -- DIR --twice`로 재생한다. 재생 결과를 기록된 상태 다이제스트와 대조하고, 결정론까지 검사한다.
- **게임플레이 지표**: 시나리오는 함장별 DPS·받은 피해·격파 시간을 요약하고(`--metrics DIR`이면 JSONL), `server --metrics FILE.jsonl`은 실서버 교전을 초 단위로 남긴다. 밸런스 시트에는 「교전 수치」 표가 있다.
- **3D 재생**: `client --replay DIR [--as 함장] [--from 초] [--speed 배속]`으로 같은 기록을 그 함장 시점으로 본다. 다이제스트 판정을 출력하고, `STARFALL_FIXED_FPS`와 `--shot`으로 같은 장면을 매번 같은 이미지로 찍는다.
- **수치는 코드 밖에**: `tuning/*.ron`을 고치고 `cargo run -p sim --release --example balance -- --write docs/BALANCE.md`로 diff를 본다(재컴파일 없음, `STARFALL_TUNING=DIR`로 다른 수치 비교).
- **숫자로 하는 화면 검증**: `STARFALL_FIXED_FPS=60`(같은 명령이면 같은 이미지), `STARFALL_HIDE_UI=1`(HUD 제거), `python tools/imgdiff.py A.png B.png`(유사도·변화 영역·밝기/채도).

## 렌더링

- **하늘**: 화면 픽셀마다 정확한 시선 방향을 다시 계산하고, 정수 해시(PCG3D) 노이즈에 옥타브마다 회전을 주어 성운에 각진 자국이 생기지 않는다. 기존 부동소수점 해시는 정밀도가 부족해 성운에 찢긴 다각형 모양의 경계가 생겼다.
- **항성**: 가장자리로 갈수록 어둡고 붉어지며, 백반·흑점 주변부·채층 테두리를 그린다. 코로나에는 방사형 줄기가 있고, 정면 시야에서는 렌즈 글레어(가로 줄무늬·회절 스파이크)가 보인다. 카메라가 코로나나 워프 지점의 빛무리 안에 들어가면 그 빛이 서서히 사라져 화면이 뿌옇게 덮이지 않는다.
- **블룸**: 밝기 임계값을 넘는 것만 번진다(항성·엔진·빔·폭발). 함체와 성운은 선명하게 유지된다.
- **우주 연무**: 성계마다 성운 색으로 은은한 거리 안개를 깔고, 항성 쪽은 빛을 받아 밝아진다. 먼 함선과 암석이 검은 실루엣으로 떠 보이지 않는다.
- **보조광**: 성운 쪽에서 그림자 없는 약한 빛을 비춰, 그늘진 면도 형태가 보인다.
- **엔진**: 화염의 가장자리를 부드럽게 했고, 노즐 출구에는 카메라를 향하는 발광 원판을 두어 뒤에서 봐도 엔진이 켜져 보인다.
- **우주 먼지**: 함선 크기에 맞춘 먼지 입자가 속도 방향으로 늘어나며 지나가 비행 속도감을 준다.

## 사운드 · 음악

모든 음악과 효과음은 CC0(퍼블릭 도메인)이다. 출처·작가·가공 내역은 `crates/client/assets/music/CREDITS.md`와 `crates/client/assets/sfx/CREDITS.md`에 있다.

- **음악 6곡** (모두 −18 LUFS로 음량을 맞춰 크로스페이드가 튀지 않는다)
  - 안전 성계: 탐험곡 3곡을 성계에 따라 돌린다.
  - Wild·War Zone·Deep: 긴장감 있는 앰비언트를 튼다.
  - 교전: 전투곡 2곡을 교전마다 번갈아 튼다.
  - F2 음소거, `-`/`=` 음량.
- **효과음 40개** (Kenney Sci-Fi/Impact/Interface, rubberduck 50 CC0 Sci-Fi SFX)
  - 무기: 전투기 레이저, 포탑 포격(낮춘 음정), 주포(충전 방전 + 저역 굉음), 미사일
  - 피격: 실드 피격, 선체 피격(경·중), 폭발(소형, 대형은 저역 레이어 추가)
  - 이동: 워프 충전·도약, 함급별 엔진 루프(전투기·순양함·주력함, 추력에 따라 음량·음정 변화), 부스트 루프
  - 기타: 도킹 중 정거장 기계음, 목표 고정, 도킹·출항, 스캔, 채굴, 선체 30% 미만 경보, 오류·알림음
- 같은 효과음은 변형을 돌아가며 쓰고 음정도 조금씩 달리해 반복감이 없다. 카메라와의 거리에 따라 감쇠한다. 난전에서는 피격음 빈도를 제한한다.
- 파일이 없으면 기존 합성음(`client --dump-sfx DIR`로 확인 가능)으로 대체한다.
- `STARFALL_SFX_LOG=1`을 켜면 10초마다 실제로 재생된 효과음 종류별 횟수를 로그로 남긴다(귀 대신 텍스트로 확인).

## 성능

측정 도구:

```
cargo run -p sim --release --example bench 1000                       서버 단독: N명 War Zone 난전의 틱 시간·송신량
cargo run -p bot --release --example swarm -- ws://HOST:7777 1000 60     실소켓 N명이 접속·워프·교전 (서버는 --dev 권장)
client --bench 20   (STARFALL_BENCH_SCALE=15 → 약 1000척)                 클라이언트 함대전 프레임 시간 (V-Sync 끔)
client --dump-sfx DIR                                                    합성 효과음을 WAV로 출력
```

서버는 접속자가 있으면 10초마다 `[stats]` 줄로 단계별 틱 비용과 접속자당 송신량을 출력한다.

텍스트 프로파일러(`shared::prof`): 서버 벤치와 `client --bench`는 끝에 호출 트리 표(호출 수, 총·자기 시간, ms/tick 또는 ms/frame, 비율)와 가장 비싼 구간 목록을 출력한다. 실서버는 `server --prof`(또는 `STARFALL_PROF=1`)로 `[stats]`와 함께 낸다.

### 1000명 동시 교전

한 성계에 1000명이 모여 싸우는 상황을 실제 WebSocket 1000개로 검증했다(`swarm`, 서버와 같은 PC 12코어).

| 항목 | 이전 | 현재 |
|---|---|---|
| 접속·교전 완주 | — | 1000/1000, 60초 교전 중 격침·재출격 3500회 |
| 접속자당 수신 스냅샷 | — | 19.9 / 20 Hz |
| 서버 틱 (예산 50 ms) | 107 ms (서버 벤치) | 평균 13–22 ms, 간헐 최대 ~110 ms |
| 접속자당 송신량 | 3.9 MB/s | 약 195 KB/s |
| 클라이언트 2500척 렌더 | — | 70 fps (1600×900) |

- 접속자별 관심 영역 스냅샷: 내 함선·호위함·목표는 매 틱, 나머지는 거리·크기 우선순위로 틱당 192척까지(클라이언트가 속도로 보간), 처음 보는 엔티티는 가까운 순으로 틱당 128개씩 소개.
- 스냅샷은 바이너리 프레임(엔티티당 39바이트), 효과는 9 km 이내만 최대 96개. 접속자별 생성·인코딩을 병렬 처리.
- 공간 격자 타겟팅, 포탑 재조준 0.5초 분산, 교전 배너 1초 스로틀, 성계당 잔해 48개 상한.
