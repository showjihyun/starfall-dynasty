# 실서버 소크 QA (서버가 하루를 버티는가)

```
cargo build --release -p server
cargo run -p bot --release --example soak -- [--minutes 30] [--captains 40] [--session 4] [--port 7795] [--log FILE]
```

실제 서버 바이너리를 띄우고 봇 함장 N명이 몇 분–하루 동안 접속해 논다(`crates/bot/examples/soak.rs`): Frontier 고리(Orion Drift,
Vesta Corridor, Kharz Forge)에서 해적을 쫓아 쏘고, 2분 반마다 워프하고, 격침되면 재건하고, `--session`분마다(엇갈려) 접속을 끊었다가
몇 초 뒤 토큰으로 돌아온다. 30초마다 서버 메모리(RSS), 서버가 스스로 재는 틱 비용(`[stats]`), 저장 데이터 크기, 접속 수, 재접속
실패를 적는다. 끝나면 서버를 **강제로 죽이고**(정상 종료가 아니라 사고처럼 — 15초 자동 저장이 남긴 것만 남는다) 같은 데이터로 다시
띄워, 모든 함장이 토큰으로 돌아와 자기 함장을 찾는지 본다.

판정(하나라도 FAIL이면 exit 1):

| 검사 | 기준 |
|---|---|
| 서버가 살아 있음 | 끝까지 프로세스 유지 |
| 재접속 실패 없음 | 0 |
| 재시작 뒤 전원 복귀 | 토큰 로그인 + 프로필 |
| 메모리가 오르지 않음 | 준비 구간(처음 1/5) 뒤 기울기 < 10.7 MB/h (하루 +256 MB 미만) |
| 틱 비용이 오르지 않음 | 마지막 1/4 평균 ≤ 처음 1/4 × 1.5 + 0.5 ms |
| 예산을 넘는 틱 없음 | 최악 틱 < 50 ms (20 Hz) |

`--log FILE`: 서버를 `--prof`로 띄우고 서버가 찍는 모든 줄(10초마다 구간 프로파일 포함)을 FILE에 남긴다 — 튄 틱의 원인을 볼 때.

**측정 중에는 다른 무거운 작업(빌드·테스트)을 돌리지 말 것** — 숫자가 무효가 된다. (첫 측정의 145 ms를 처음엔 그 탓으로 봤지만,
기계를 비운 재측정에서도 203 ms가 나왔다: 진짜 원인은 아래.)

## 측정 (2026-11-08, 40명, 세션 4분)

| 실행 | 최악 틱 | 메모리 | 재시작 복귀 | 판정 |
|---|---|---|---|---|
| 30분 (같은 기계에서 빌드·테스트 동시 실행 — 무효) | 145 ms | 18.9 → 20.5 MB | 40/40 | 틱 FAIL |
| 30분, 기계를 비움 | **203 ms** (15–21분) | 18.9 → 21.8 MB (+4.4 MB/h) | 0/40 (도구 문제: 재시작 서버를 2초만 기다림) | 틱·재시작 FAIL |
| 25분 `--log` (원인 찾기) | 154 ms | 19.1 → 23.5 MB | 40/40 | 틱 FAIL |
| **25분, 수정 뒤** | **5.4 ms** | 16.2 → 17.5 MB (+2.3 MB/h) | 40/40 | **전부 PASS** |

원인: 엔티티 45개, 함장 40명인데 튄 틱의 71%가 「시청자별 스냅샷」(rayon 병렬)이었다. 작은 일감을 12개 작업자에게 나눠 주는
fork-join은 가장 늦은 작업자를 기다리고, 같은 기계의 봇 40명·tokio와 CPU를 다투다 작업자 하나가 밀려나면 틱 전체가 100–200 ms
멈췄다. → 시청자 × 엔티티가 16384 미만이면 한 스레드에서(`interest.rs` `PARALLEL_SNAPSHOT_WORK`), 병렬일 때도 작업 하나에 8명 이상,
서버 인코딩도 32개씩 묶음. 1000척 벤치는 그대로(11.2 ms, 같은 날 기준).

| 10분 **200명** | 4.4 ms | 55.7 → 58.6 MB (+5.0 MB/h) | 200/200 | 전부 PASS (세션 562) |

| 24시간 시도 (40명, 2026-11-08) | 0.9 ms (기계를 쓰던 57–74분에 31–51 ms) | 14.9–21.7 MB | — | **무효**: 88.6분 다음 샘플이 623.5분 — PC가 약 9시간 잠들었고, 깨어난 뒤 봇들이 죽은 소켓에서 멈춰 있었다 |

그 뒤 도구 보완: 봇의 접속·전송에 10초 제한(`Bot::broken`이면 다시 접속), 샘플 간격이 1.5분을 넘으면 「MACHINE PAUSED」와 함께
판정 「the machine stayed awake」 FAIL. 24시간 실행은 PC가 잠들지 않게 해 두고(전원 설정) 돌려야 한다.

남은 것: 24시간 실행(`--minutes 1440`, 밤새), 봇 수를 실서버 목표(수백 명)로 — 봇은 다른 기계에서 돌려야 서버만 잰다.
