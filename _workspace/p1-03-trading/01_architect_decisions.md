## D-1 판정 — r1 `filters: FAIL`, SC-40 `trading_replay_worker` 유령 지명

**결론 먼저**: 계약 문면에 표식을 두지 않는다. **지명된 테스트의 역할(role)을 Rust 소스의 속성에서
읽는다** — `#[ignore]` 와 **부모의 spawn 리터럴**이 그 토큰이다. R28 과 같은 원리이고(verdict 임은
도구가 든 토큰이지 사람이 쓴 산문이 아니다), 다른 점은 **토큰이 enum 이 아니라 테스트 속성**이라는 것뿐이다.
계약은 고치지 않아도 이 결함이 닫힌다. 다만 **다른 결함 하나가 같은 로그에서 드러났고**(§3) 그것은
계약 한 칸과 `server/` 한 줄을 요구한다.

### 1. 필터 지명과 참조 언급을 무엇으로 가르는가 (지시 1)

**느슨하게 가는 쪽(백틱 맨 이름을 무시)을 고르지 않는다. 그 구멍을 실측했다:**

| 느슨하게 할 때 | 사라지는 것 |
|---|---|
| 맨 이름 전부 무시 | 필터 66 → **cargo 61 만**, 그리고 **§1 SC 32 개가 분모에서 통째로 사라진다**(필터를 가진 SC 78 → 46). 사라지는 번호: SC-56·61~64·66·67·69·70·72·73·75·76·78·79·81·82·84·85·87·88·90·91·93·94·96·97·99·100·102·104·105 — Unity 맨 이름이 유일한 지명인 화면 항목이 대부분이다 |
| Rust 맨 이름만 무시 | 오늘 전멸하는 SC 는 0 이지만 SC-13·21 의 **Rust 검증이 각각 2 필터 줄어든다**(SC-13: 3→1, SC-21: 3→1) |
| p0-01 계약에 같은 규칙을 소급 | 그 슬라이스는 cargo 0 + 맨 이름 6 이라 **Rust 분모가 0 이 된다** |

**거짓 지명 1 건을 피하려고 진짜 지명 40 건(TEST_FN 40 = Rust 5 + Unity 35)을 버리는 거래다.
40 : 1.** 그리고 사라진 쪽은 "필터가 안 돌았다"로 빨간불이 되지 않고 **분모에서 조용히 빠진다**
(지시 4 가 금지한 형태).

**`cargo test …` 명령만 지명으로 읽는 쪽도 고르지 않는다** — 그것이 위 표의 첫 줄이다.

**고른 것: 지명은 지금처럼 전부 줍는다. 가르는 것은 "지명이냐"가 아니라 "그 지명을 게이트가 어떻게
만족시키느냐"다.** 역할을 소스에서 읽는다.

```
역할 분류 (Rust TEST_FN 필터마다 정확히 하나, 소스에서만 결정)
  RUNNABLE  : #[test] 에 #[ignore] 없음            → 자기 실행에서 ran >= 1
  CHILD     : #[ignore] 있고, 그 이름이 같은 파일의 문자열 리터럴로 나온다(부모가 spawn)
              → 단독 실행하지 않는다. ① --list --ignored 로 존재 1 건, ②
                같은 SC 가 지명한 부모 필터의 로그에 자식 실행 줄이 있고 그 수를 찍는다
  MANUAL    : #[ignore] 있고 부모 리터럴 없음      → 게이트가 --ignored 를 붙여 돌리고 ran >= 1
```

**왜 이것이 R28 과 같은 원리인가**: 계약에는 컴파일러가 없다. 그래서 **계약에 표식을 두지 않았다.**
표식을 든 것은 Rust 쪽이고, 둘 다 **오타가 조용히 면제로 바뀌지 않는다**:

- `#[ignore]` 는 속성이다. 철자가 틀리면 `cargo` 가 unknown attribute 로 거부한다.
- 부모의 `"trading_replay_worker"` 리터럴은 **실행에 쓰이는 인자**다. 이름이 틀리면 자식이 0 건을
  돌리고 **부모 테스트가 깨진다.** `참고:` 산문과 결정적으로 다른 점이 이것이다 — 이 문자열은
  장식이 아니라 **하중을 받는다.**

### 2. `#[ignore]` 지명이 정당할 수 있는가 (지시 2)

**정당하다. 다만 두 종류이고 게이트의 의무가 다르다.**

- **MANUAL**: 정당하고, **그때는 게이트가 `--ignored` 를 붙여 돌려야 한다.** 그 뜻은 계약이 아니라
  소스(부모 리터럴 없음)가 싣는다. 오늘 해당 0 건이므로 이 규칙은 **지금 비용이 0**이고, 누가
  `live_smoke` 를 계약에 적는 순간 켜진다.
- **CHILD**: `--ignored` 를 붙여 돌리는 것은 **틀린 처방이다. 실측으로 확인했다** —
  `test result: FAILED. 0 passed; 1 failed`. 자식은 부모가 넣는 환경 변수 둘 없이는 패닉한다.
  게이트가 플래그만 붙이면 **옳은 구현이 FAIL 로 바뀐다.** (게이트가 환경 변수를 채워 주는 쪽은
  부모를 게이트 안에 다시 구현하는 것이고, 그러면 "두 프로세스" 를 재는 주체가 둘로 갈린다.)

### 3. 같은 로그가 드러낸 두 번째 결함 — SC-40 의 "두 프로세스" 에 관측이 없다

r1 부모 로그에서 **`trading_replay_worker` 가 한 번도 안 나온다**(실측 `grep -c` = 0). 부모는 자식
stdout 을 `assert!` 의 **실패 메시지 안에서만** 쓴다(`trading_replay.rs:699-701`). 즉 **성공 경로에
자식의 흔적이 없다.**

**그래서 부모가 spawn 을 그만두고 같은 프로세스에서 두 번 돌도록 바뀌어도 로그는 똑같이 초록이다.**
SC-40 의 검증 항목 문구는 *"서로 다른 프로세스에서 2 회"* 인데 **그 절반이 아무 관측도 갖고 있지 않다.**
§8.2 형태 (나) 검출기 사망형이고, 리더가 같은 라운드에서 고친 둘("계약이 요구한 것을 도구가 재지 않는")과
**같은 가족이다.** 이 유령 건은 그 결함이 **드러난 자리**지 그 결함 자체가 아니다.

고치는 방법은 한 줄이다: 부모가 자식 stdout 을 **성공 경로에서도 찍는다**. 그러면 자식의
`test trading_replay_worker ... ok` 가 부모 로그에 2 번 들어오고, **CHILD 역할의 ② 가 실측 가능해진다.**
(rust 몫. §9)

### 4. 분모를 깨지 않는다 (지시 4)

`executed 66 · ran_ge_1 65` 의 **66 은 그대로 66 이다.** CHILD 행은 분모에서 빠지지 않고
**자기 행으로 남아 다른 조건으로 만족된다.** 매 실행 찍는 수:

```
Rust 필터 66 = RUNNABLE 65 + CHILD 1 + MANUAL 0              (항등식 ①)
실행 65 + 자식 입증 1 = 66 · ran_ge_1 66                      (항등식 ②)
레포 #[ignore] 5 = CHILD 3 + MANUAL 2 + 미분류 0               (항등식 ③)
계약이 지명한 #[ignore] 1 = CHILD 1 + MANUAL 0
CHILD 행마다: --list --ignored 건수 1 · 부모 로그의 자식 실행 수 N (SC-40 기대 N=2)
```

- **항등식 ③ 이 자기 무력화 방어다.** 누가 속성을 재포맷해 정규식이 안 먹으면 **"위반 0" 이 아니라
  미분류 ≥ 1 → exit 4.** R28 항등식 ① 과 같은 장치다.
- **기대값 2 는 게이트에 박지 않는다.** 게이트는 수를 찍고, **그 수가 2 여야 한다는 것은 계약
  SC-40 의 `⊘` 칸이 말한다**(§8 제안 문구). 수를 도구에 박으면 계약이 요구하지 않은 수가 생긴다.
- **음성 대조**(규칙 6): `Fixes` 에 `ignore_role: bool = True` 를 더하고 **selftest 가 끈다** →
  SC-40 행이 **다시 유령 1 건**이 되어야 한다. 끈 판이 초록이면 그 검출기는 죽었다.

### 5. 이 설계에 규칙 1 을 돌린다 (지시 3) — **못 거르는 것**

| 형태 | 거르는가 | 비고 |
|---|---|---|
| 계약이 **존재하지 않는 테스트**를 지명 | **거른다** | 맨 이름은 정적 GHOST(오늘 0), cargo 명령 이름은 ran=0 유령. 이 설계가 바꾸지 않는다 |
| 지명은 맞고 **그 경로가 안 도는** 때 | **못 거른다** | 이 게이트는 *"그 이름의 테스트가 돌았다"* 만 잰다. 제품 경로 실행은 §1 `⊘` 칸이 유일한 방어다. 이 설계로 나아지지 않는다 |
| 한 행에 **명령이 둘 이상** | **거른다(수로는)** | 오늘 8 행(SC-05·07·26·41·42·44·51·54, 최대 4). 명령마다 자기 필터 행이 된다 |
| 한 행의 두 명령 중 **하나만 verdict**이고 하나는 예시 | **못 거른다** | 이번 결함의 cargo 분기 쌍둥이다. cargo 명령은 `#[ignore]` 같은 토큰을 안 들고 있어 가를 근거가 없다 |
| **산문에 적힌 RUNNABLE 테스트 이름** | **못 거른다 — 남는 가장 큰 구멍** | 그 이름은 돌고 초록이 되어 **분자를 부풀린다.** 오늘 그 혼입을 재는 유일한 수는 `cross_sc`(다른 SC 도 잡는 테스트, 실측 **0**)이고, 그것은 *다른 SC 가 같은 테스트를 지명할 때만* 걸린다 |
| 부모가 **다른 파일·크레이트**에 있는 자식 | **틀리게 거른다** | MANUAL 로 분류돼 `--ignored` 단독 실행 → **거짓 빨간불.** 조용한 초록이 아니라 시끄러운 빨강이므로 방향은 맞지만 구멍이다. 오늘 자식 3건 전부 같은 파일(실측) |
| 매크로가 만든 테스트 · `cfg!` 뒤의 `#[ignore]` | **exit 4 로 멈춘다** | 미분류 ≥ 1. 조용히 통과하지 않는다 |
| 부모가 spawn 을 그만두고 in-process 로 바뀜 | **§3 을 고친 뒤에만 거른다** | 고치기 전에는 아무것도 못 잡는다(실측 grep 0) |
| `#[cfg(not(debug_assertions))]` 릴리스 전용 테스트를 표준 게이트가 지명 | **이 설계 밖** | 실측: 릴리스 전용 함수 1(`r4_s3_release_arm_signals_without_fabricating_an_event`)이고 **계약은 지명하지 않는다**. `--release` 를 든 필터는 1(SC-07) |

### 7. 소급 (지시 6) — **재판정하지 않는다. 실측 근거가 있다**

**p1-01·p1-02·p0-01·p0-02 네 계약을 현행 추출기로 다시 돌렸다:**

| 슬라이스 | §1 행 | Rust 필터 | `#[ignore]` 지명 |
|---|---|---|---|
| p1-01 | 90 | 19 (cargo 19 + 맨 0) | **0** |
| p1-02 | 114 | 71 (cargo 63 + 맨 8) | **0** |
| p0-02 | 74 | 6 (cargo 3 + 맨 3) | **0** |
| p0-01 | 38 | 6 (cargo 0 + 맨 6) | **0** |

**네 슬라이스 합쳐 `#[ignore]` 지명 0 건이다.** 이 변경이 바꾸는 것은 `#[ignore]` 지명의 처리뿐이므로
**과거 PASS 항목의 출처가 하나도 다시 평가되지 않는다.** R28 §9 의 논증과 같다 — 드러난 건이 전부
"도구는 맞고 분류가 없었다" 이고 "도구가 남의 항목을 판정했다" 가 0 건이다.

**이 수의 한계를 적어 둔다**(규칙 9): 이 분류는 **오늘의 소스**로 쟀다. 당시 RUNNABLE 이었다가 지금
`#[ignore]` 가 된 테스트가 있으면 위 표에 지명으로 나타날 텐데, **0 이므로 그 경우도 없다.**

**되돌리는 조건(기계가 보는 형태)**: r2 이후 어느 라운드에서든 **`#[ignore]` 지명 수가 0 이 아닌 과거
슬라이스 계약이 나오면**(CI 의 `--contract` 가 p1-02 를 가리키는 동안 포함) 그 SC 의 PASS 를 다시 연다.
`gates.yml --contract` 를 이 계약으로 옮기는 만기(§9 2행)가 그 수를 CI 에서 보이게 하는 자리다.

### 8. 제안 계약 문구 — **적용하지 않았다**(동결). 리더가 해제 시점을 정한다

**(제안 1) `02_sprint_contract.md:306` SC-40 의 `⊘` 칸** — 현재 문구 뒤에 **한 절 추가**.

## D-2 판정 — 자식 관측이 **표준 게이트 로그에 닿는 경로**. raw write 는 틀렸다(실측)

qa 가 D-1 역할 분류를 구현해 `filters` 가 PASS 되고 유령 1 → 0 이 됐다(`evidence/r1_20261010h`,
항등식 ①②③ 성립 · 미분류 0 · 분모 66 유지). **만기 #5 하나만 0 이다** — CHILD 의 부모 로그 자식 실행 수.

qa 가 올린 질문은 *"rust 가 캡처를 우회하는 경로(raw `std::io::stderr()` write 등)로 바꾸면
`--workspace` 로그에도 들어오는가"* 이고, **가설이라고 명시했다.** 실측했다 — **가설의 앞쪽은 맞고
뒤쪽이 틀렸다. 그 경로를 고르면 안 된다.**

### 0. 실측 — 격리한 스크래치 크레이트(레포 밖, `…/scratchpad/capture`)

레포의 `server/` 를 건드리지 않고 같은 조건만 재현했다. 돌고 있는 판정과 target 을 공유하지 않는다.

| 잰 것 | 값 |
|---|---|
| 성공한 테스트의 `println!`·`eprintln!` | **로그에 안 나온다** (libtest 가 삼킨다 — qa 측정과 일치) |
| 성공한 테스트의 raw `stdout().write_all` · `stderr().write_all` | **나온다** (캡처를 우회한다 — qa 가설의 앞쪽은 참) |
| **그런데**: raw write 180 건 · 병렬 6 테스트 | **`test t2 ... [CHILD] worker=w6 …` 로 한 줄이 splice 됐다.** 마커 179/180 · `test X ... ok` 줄 **5/6** |
| raw write **12 건**(실제 규모: 부모 3 × 자식 2) · 병렬 · **25 회 반복** | **1 / 25 회 오염** (`ok` 줄 5/6) |
| raw write + **`--test-threads=1`** · 5 회 | **5 / 5 회 오염, `ok` 줄 0/6** — 결정적으로 깨진다 |
| `println!` + **`-- --show-output`** · 병렬 10 회 + 단일 스레드 3 회 | **0 / 13 회 오염.** 마커 12/12 · `ok` 줄 6/6 |

**왜 splice 되는가**: libtest 는 병렬·단일 모두 `test <이름> ... ` 과 `ok\n` 을 **두 번에 나눠 쓴다.**
테스트 안에서 나간 raw write 가 그 사이에 끼면 **그 테스트의 결과 줄이 사라진다.**

### 1. 결정 — raw write 를 고르지 않는다. **코드가 아니라 명령을 바꾼다**

**`cargo_sc_map.py` 의 `TEST_LINE` 은 `^test (\S+) ... (ok|FAILED|ignored)` 를 읽는다.
splice 된 줄은 그 정규식에 안 걸린다 → 그 테스트는 `ran=0` → 게이트가 유령으로 찍는다.**

즉 raw write 는 **고치려는 결함을 flake 로 재생산한다**: 자식 관측을 얻는 대가로
**부모가 거짓 유령이 되는 4% 짜리 복권**을 사고, `--test-threads=1` 이 끼면 **100%** 가 된다.
CLAUDE.md 가 p1-01 에서 데인 네 형태 중 *"flaky 테스트가 자기 폴링 비용을 쟀다"* 와 같은 자리다 —
**관측 장치가 관측 대상을 망가뜨린다.**

**rust 의 §9.7 이행은 옳다. 고칠 것이 없다.** `println!` + 자식 stdout 의
`test result: ok. 1 passed` **단언**(이름 오타가 부모를 깨뜨린다)은 그대로 둔다. 바꿀 것은 **명령**이다:

```
표준 게이트:  cargo test --workspace --locked -- --show-output
계약 §1 SC-40 방법 칸의 명령도 같은 꼬리표를 붙인다
```

**게이트 파싱 앵커**(실측한 형식):

```
---- sc40_two_process_replay_with_trading_is_byte_identical stdout ----
[CHILD] worker=trading_replay_worker run=1 child_pid=… parent_pid=… :: test result: ok. 1 passed
[CHILD] worker=trading_replay_worker run=2 child_pid=… parent_pid=… :: test result: ok. 1 passed
```

`---- <부모> stdout ----` 블록 **안에서만** `[CHILD] … :: test result:` 를 센다. 블록 밖의 같은 문구는
세지 않는다 — 그렇게 하면 부모 귀속이 로그 구조로 보장된다.

**qa 가 `--nocapture` 를 게이트에 붙이지 않은 판단이 맞다.** 그 이유가 일반화되는 것이 이 판정의 핵심이다:
**증거는 게이트 전용 실행이 아니라 표준 실행의 로그에 있어야 한다.** `--show-output` 은 그 요구를
`--workspace` 에서 만족시키는 유일한 무해 경로다(raw write 는 무해하지 않다, §0).

### 2. qa 의 두 수 분리를 받는다 — D-1 §A 의 정정이 수로 보인다

`child_mentions` 와 `child_runs` 를 따로 찍고 `... ignored` 줄은 **실행으로 세지 않는** 것,
그리고 `gates/test.log` 에 대고 돌리면 **언급 1 · 실행 0** 이 나오는 것 — 그것이 §A 가 말로 적은
*"있는 이름이 건너뜀 기록이고 실행 기록은 없다"* 의 기계 형태다. 그대로 유지한다.

기대값 2 를 게이트에 박지 않고, **부모 로그가 없으면 0 이 나오는 것을 selftest 가 돌연변이로 단언**한
것도 맞다(§9.6 이행). `⊘` 칸이 적용되면 `child_runs` 가 그 칸의 입력이 된다.

### 3. 부수 발견 — `-q` 는 유령 검출기를 통째로 눈멀게 한다

실측: `cargo test -q` 는 `test X ... ok` 줄을 **아예 찍지 않는다**(점 진행 표시로 대체).
`cargo_sc_map.py` 의 `TEST_LINE`·`RESULT_LINE` 중 전자가 전부 0 이 되어 **모든 필터가 유령이 된다**
(또는 누군가 그 상황에 맞춰 집계를 느슨하게 고치면 **전부 초록이 된다** — 더 나쁜 쪽).

**게이트 명령에 `-q`·`--quiet` 를 넣지 않는다.** 이 문장을 적어 두는 이유는 `--show-output` 을 붙이면
로그가 커지고, **커진 로그에 대한 자연스러운 대응이 `-q` 라서**다. 그 대응이 검출기를 죽인다.

### 4. qa 가 가져올 수 하나 (분모 있는 형태)

`-- --show-output` 은 **레포 전체의 통과한 테스트 stdout 을 다 찍는다.** 내가 잰 것은 격리 크레이트
6 테스트이고, **실제 워크스페이스의 로그 증가량은 측정하지 않았다.**

| 가져올 수 | 분모 | 판단 |
|---|---|---|
| `gates/test.log` 바이트 수: `--show-output` 없음 → 있음 | 현행 로그 크기(r1 의 `gates/test.log`) | 증가가 감당 가능하면 **표준 게이트에 붙인다.** 감당 불가면 리더 판단 — 다만 **"세 부모 바이너리에만 붙이기" 는 증거를 게이트 전용 실행으로 되돌리는 것**이므로 그 쪽을 고르면 만기 #5 는 **닫히지 않은 채로 남는다** |
| 다중 패키지 워크스페이스에서 `--` 뒤 플래그가 **모든 테스트 바이너리**에 전달되는지 | 바이너리 수 | 나는 **단일 패키지에서만 확인했다.** qa 가 실제 `--workspace` 실행 한 번으로 확인한다 |

### 5. 만기 #5 는 열린 채로 둔다 — 종료 조건을 좁힌다

| 수 | 종료값 |
|---|---|
| **표준 게이트 로그**(`cargo test --workspace --locked -- --show-output`)의 `child_runs` | 부모마다 **≥ 1** (SC-40 은 계약이 **2** 를 요구) |
| 그 로그의 `child_mentions` − `child_runs` | **0** (언급만 있고 실행이 없는 상태가 남지 않는다) |
| 같은 로그의 `test X ... ok` 줄 수 | **splice 0** — raw write 를 고르지 않았음의 사후 확인 |
| 분모 | **`#[ignore]` 자식을 spawn 하는 부모 수 = 3** (D-1 후속 §C 그대로) |

**`mining_replay.rs`·`determinism.rs` 는 qa 가 확인하지 않았다**(p1-03 계약이 지명하지 않아 CHILD
필터가 없다). **분모 3 은 줄이지 않는다** — 셋 중 둘이 "확인 안 했다" 라는 사실이 출력에 남아야 한다.
세 부모가 전부 `println!` 로 통일되면 `--show-output` 하나로 셋이 같이 닫힌다.
