> ⚠ **정정 있음 — `08-correction.md`를 함께 읽어라.** (qa3 지적, 2026-09-23)


**수행**: 리더가 환경을 세우고 절차를 안내, **사용자가 직접 조종·관찰.** 에이전트 주간 한도로 qa2·client 불가.
**이 문서는 판정이 아니라 관찰 기록이다. 판정은 qa2 몫.**

## 왜 사람이 해야 했는가 (계약 §0.10, 스펙 §11-7)
> 손 방향 부호가 통째로 뒤집혀도 자동 검증은 전부 통과한다. 서버와 클라이언트가 **같은 공식**을 쓰므로
> 예측 오차 0, fixture 왕복 통과, 결정성 바이트 동일까지 전부 초록이다. 특히 오토레벨의 `sin_err` 부호
> 한 줄이 그 위험을 진다(ADR-0010 §2.1). **검출기는 SC-59의 육안 관찰 하나뿐이다.**

라운드 1~4에서 나온 **모든 PASS가 부호에 대해서는 아무것도 증명하지 못했다.** 자동 입력 + 자동 판정은
같은 부호 규약을 공유하므로 항진명제가 된다 — 그래서 자동화하지 않았다.

## 이 관찰이 자동 검증과 연결되는 지점
- **a**: ADR-0009 §1의 축 고정(`thrust_z` → 로컬 +Z)이 화면에서도 성립.
- **c**: server SC-18의 `v = (-1.25, 0, 1.75)`(경계 당김과 추력이 한 벡터에 동시 존재)가
  **"플레이어가 경계에 갇히지 않는다"**를 뜻함을 처음 확인.
- **d**: AC-4(g2)의 "진동 없음"이 덮지 못하던 **"수동 롤 중 복귀 정지"**를 확인.

2. **⚠ 재조정 지표** — `02-clip-a-extended.md` §2. `reconcile_hard_snap_total` 1 → **5**(목표 0),
   `reconcile_error_m` max **56.3 m**(p99 0.0012), `reconcile_error_deg` max **80.6°**(p99 1.1), n=1013.
   00_request가 증명하겠다고 한 **3번 항목**에 직접 걸린다. 계약 §7: 임계 초과 시 임계값을 늘리지 말고 architect 통지.
