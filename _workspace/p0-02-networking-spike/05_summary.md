## 설계 단계에서 잡은 결함 (구현 전)

검토에서 차단 요소 5건이 나왔고 전부 반영됐다. 값이 컸던 순서:
1. **tick 재개 규칙 부재** — 서버 재기동 시 같은 `(world_id, tick)` 충돌로 **트랜잭션 전체가 중단되어 멀쩡한 이벤트까지 유실**. 실제 PostgreSQL에서 재현 확인. 타이밍 의존이라 나중에 발견했다면 원인을 봇·네트워크로 오진했을 종류다.
2. **Windows 타이머 해상도** — `tokio::time::sleep(50ms)`가 실제 61ms. 코드 품질과 무관하게 성능 게이트 100% 실패. 전용 OS 스레드로 해결(p50 50.3ms).
3. **항진명제 검사 2건** — `ws_connections == opened − closed`, `tick_skipped_total == 0`. 코드가 어떻게 틀려도 통과. 독립 출처로 교체하고 **I-25("검증은 출처가 독립일 때만 검증이다")**를 불변식으로 승격.
4. **생성기가 계약의 좁힘을 무시** — 이후 모든 제약이 조용히 무시될 뻔함.
5. **유효 fixture 개수 오류(16→12)** — 그대로 두면 테스트가 영원히 실패.

## 구현·평가 중 잡은 결함

- 서버 자체 발견 4건: 정상 Close 15초 지연, 폭주 클라이언트의 거부 응답 유실, stdin 종료가 BOM 때문에 무시, 검사가 주석에 걸리는 오탐
- QA 도구 결함 3건(실서버 아니면 안 드러남): `close_initiator`가 Close 교환의 나중 값으로 덮여 **SC-52가 모든 정상 세션에서 거짓 FAIL이 될 뻔함**, envelope `tick` 비교 누락, 기대값 오류 2건
- 클라이언트 자기 정정 1건: 필드 개수 계산 착오 → 총계를 게이트에서 내리고 필드별 표를 근거로 교체
